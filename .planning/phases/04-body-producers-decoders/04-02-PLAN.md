    ```typescript
    // D-10: Never instanceof ZodError — duck-type .issues array across module boundaries
    function normalizeSchemaError(error: unknown): DecodeIssue[] {
      if (
        error !== null &&
        typeof error === "object" &&
        "issues" in error &&
        Array.isArray((error as { issues: unknown }).issues)
      ) {
        return ((error as { issues: unknown[] }).issues).map((issue) => {
          const i = issue as Record<string, unknown>;
          return {
            path: Array.isArray(i["path"]) ? (i["path"] as (string | number)[]) : [],
            message: typeof i["message"] === "string" ? i["message"] : String(i),
            code: typeof i["code"] === "string" ? i["code"] : undefined,
          } satisfies DecodeIssue;
        });
      }
      return [{ path: [], message: error instanceof Error ? error.message : String(error) }];
    }
    ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| response.body → readBytes | Untrusted HTTP response body bytes flow into memory buffer |
| JSON.parse → schema.safeParse | Attacker-controlled JSON is parsed and forwarded to consumer schema |
| schema.safeParse → DecodeIssue[] | Schema error details from third-party library cross into library's error type |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-02-01 | Denial of Service | `readBytes()` — unbounded memory allocation for response body | accept | Decoders intentionally buffer full response body; library consumers choose which decoder to use. Preview byte cap is in preview.ts (separate concern). Consistent with undici/ky/reqwest design. |
| T-04-02-02 | Denial of Service | TCP connection leak — reader not cancelled | mitigate | `finally { await reader.cancel().catch(() => {}) }` required on EVERY `getReader()` call in readBytes, Decode.none(), and Decode.optional(). This is P3 in VALIDATION.md — non-negotiable. |
| T-04-02-03 | Information Disclosure | `normalizeSchemaError` — Zod error `.message` fields may contain user-submitted data | accept | DecodeIssue messages are schema-defined strings; library doesn't inject them. Consumer controls whether to surface them in API responses. No additional sanitization at this layer. |
| T-04-02-04 | Tampering | `Decode.json` — `JSON.parse` prototype pollution via `__proto__` key | accept | Node 24 V8 JSON.parse does not allow `__proto__` to prototype-pollute. Per ASVS L1, this is a platform-level guarantee. If consumer uses older Node, they opt in to that risk. |
</threat_model>
