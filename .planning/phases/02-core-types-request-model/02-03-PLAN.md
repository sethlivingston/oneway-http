```typescript
import type { ClientSpec, QueryValue } from "./types.js";

export function mergeHeaders(
  base: Record<string, string | undefined> | undefined,
  override: Record<string, string | undefined> | undefined,
): Record<string, string> {
  const result: Record<string, string> = {};
  for (const [key, value] of Object.entries(base ?? {})) {
    if (value !== undefined) result[key.toLowerCase()] = value;
  }
  for (const [key, value] of Object.entries(override ?? {})) {
    if (value !== undefined) result[key.toLowerCase()] = value;
  }
  return result;
}

export function mergeQuery(
  base: Record<string, QueryValue | readonly QueryValue[] | undefined> | undefined,
  override: Record<string, QueryValue | readonly QueryValue[] | undefined> | undefined,
): Record<string, QueryValue | readonly QueryValue[]> {
  const result: Record<string, QueryValue | readonly QueryValue[]> = {};
  for (const [key, value] of Object.entries(base ?? {})) {
    if (value !== undefined) result[key] = value;
  }
  for (const [key, value] of Object.entries(override ?? {})) {
    if (value !== undefined) result[key] = value;
  }
  return result;
}

export function createClient(spec: ClientSpec): ClientSpec {
  return { ...spec };
}
```

Key implementation notes:
- **D-09 CRITICAL**: Do NOT use `{ ...base, ...override }`. Spreading `{ key: undefined }` sets `key: undefined` in the result, violating the "undefined means not specified at this layer" contract under `exactOptionalPropertyTypes`. The explicit `undefined`-filtering loop is mandatory.
- **D-10**: Header keys are lowercased via `.toLowerCase()` in both the base and override loops. This means `"Content-Type"` and `"content-type"` resolve to the same result key. If both are provided (one from base, one from override), the override wins because its loop runs second.
- **mergeQuery**: Query keys are case-sensitive (URL spec). Do NOT apply `.toLowerCase()` to query keys.
- **createClient()**: Returns a shallow copy of the spec via `{ ...spec }`. Merge semantics (combining client defaults with request-level values) are applied at `send()` time in Phase 3 using `mergeHeaders` and `mergeQuery`. The `createClient()` function itself only stores the spec.
- **Import style**: `import type` with `.js` extension (verbatimModuleSyntax, D-11 by analogy).
- **Named exports only**: `export function createClient`, `export function mergeHeaders`, `export function mergeQuery`. No default export.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Caller-supplied headers → mergeHeaders | Caller provides header key/value pairs; keys are normalized (lowercased) before storage |
| Caller-supplied query → mergeQuery | Caller provides query key/value pairs; keys stored as-is (case-sensitive per URL spec) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-03-01 | Tampering | Header value injection via undefined override silently erasing base value | mitigate | The explicit `undefined`-filtering loop (D-09) is the sole mitigation. `{ ...base, ...override }` would set `key: undefined` in the merged result, causing the header to be absent in the final `fetch()` call — silently sending requests without required headers (e.g., Authorization). The loop prevents this: `if (value !== undefined) result[...] = value`. Verified by the test `"undefined override value does NOT erase base value"`. |
| T-02-03-02 | Tampering | Header key case collision bypassing dedup | mitigate | Keys are normalized to lowercase before storage (D-10). A caller providing both `"Content-Type"` and `"content-type"` gets a single lowercase key — the last write wins. This follows HTTP/1.1 case-insensitive header field name semantics. Verified by the test `"case-insensitive dedup"`. |
| T-02-03-03 | Information Disclosure | ClientSpec contains sensitive headers (Authorization, API keys) stored in memory | accept | `createClient()` stores the spec as a plain object. The caller is responsible for managing the lifetime of the ClientSpec. This is a library — not a secret store. Consumers should not log or serialize ClientSpec objects, but that is outside the library's enforcement boundary. |
| T-02-03-04 | Tampering | Query key injection via unencoded characters | accept | Query keys are stored as-is (plain string keys). Encoding happens in `buildQuery()` (Plan 02) at send time when `URLSearchParams` is constructed. Storing unencoded keys in the merged record is correct — URLSearchParams handles encoding at construction time. No injection risk at the merge layer. |

> **Security scope note:** This plan introduces no HTTP transport, authentication, cryptography, or external I/O. The primary security property enforced is header merge correctness — preventing silent header loss via undefined propagation (ASVS V5 Input Validation: correct data handling at API boundaries).
</threat_model>
