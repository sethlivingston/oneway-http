  <action>
With `moduleResolution: Bundler`, TypeScript becomes more permissive about file extensions. The ESLint `import-x/extensions` rule is the backstop that prevents `ERR_MODULE_NOT_FOUND` in the published dist when `.js` extensions are omitted from relative imports.

Step 1 — Check if the rule is active in the current config:
Run: `npm run lint -- --print-config src/index.ts 2>/dev/null | grep -A3 '"import-x/extensions"'`

If the rule appears and is set to `"error"` (or `2`) for `.js` files, no change is needed. Document in SUMMARY.

Step 2 — If the rule is absent or set to `"off"`:
Add an explicit rule block to `eslint.config.mjs` after the `...typeAwareNarrowsConfig` spread. Insert at the end of the default export array:

```js
{
  files: ["src/**/*.ts"],
  rules: {
    "import-x/extensions": ["error", "ignorePackages", { js: "always" }],
  },
},
```

This targets only `src/` (library code). Test and tooling files are excluded since they resolve through Vitest aliases or Node resolution, not the published ESM dist.

Step 3 — Run `npm run lint` to confirm zero errors after any change.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tsconfig → TypeScript compiler | Module resolution rules change; compiler accepts more import forms |
| eslint.config.mjs → import-x resolver | Resolver uses the same tsconfig; resolver settings may change behavior post-migration |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | `moduleResolution: Bundler` extension permissiveness | mitigate | Verify `import-x/extensions` rule is active in ESLint config (Task 2). Bundler mode lets TypeScript compile `.ts` imports without `.js` but the published dist requires `.js` — the lint rule is the only enforcement backstop. |
| T-01-02 | Tampering | Stale `dist/` picked up by consumers post-migration | accept | Stale dist is a developer concern resolved by Plan 02's Vitest alias fix. TypeScript compilation does not emit to `dist/` (noEmit: true); no new risk introduced by this plan. |
| T-01-03 | Information Disclosure | `paths` entries resolve to `src/` in TypeScript IDE | accept | `paths` are IDE/type-checking only — they do not affect runtime resolution. No information leakage surface. |
</threat_model>
